---

## 🚨 为什么“让 AI 帮我做一本小说设定”还不够？

强模型很容易在几分钟内生成世界观、角色卡和剧情简介。

真正困难的是：

> **这些设定是不是作者真正想写的？它们之间有没有因果关系？能不能支撑几十万到百万字，而不是只够写一个漂亮简介？**

普通的新书设定很容易出现：

| 问题 | 常见结果 |
|---|---|
| 🏷️ **题材只有标签** | “末世 + 重生 + 系统 + AI”都写了，却没有说明每个标签到底提供什么爽点、压力或成长机制 |
| 🧠 **作者意图没被挖出来** | AI 直接替作者补完，看起来完整，实际慢慢写成另一部小说 |
| 🌍 **世界观百科化** | 设定很多名词，但规则、资源和势力并没有真正限制人物选择 |
| 🎭 **人物只有人设** | 有性格、有背景，却解释不了“他为什么此刻必须这么做” |
| 👁️ **角色拥有作者视角** | 人物莫名知道自己不该知道的信息，后续推演和剧情可信度一起崩掉 |
| ⚔️ **冲突一说就能解决** | 冲突没有利益、代价和信息差，只靠误会拖剧情 |
| 📉 **长对话后设定衰减** | 前面确认过的内容在最终总结时被遗漏、篡改或重新脑补 |
| 📋 **作者变成填表员** | AI 一项项追问字段，把创作变成录入工作 |

**纵横开书架构师解决的不是“多生成一些设定”，而是把作者的创作意图逐步收束成一套可以运行的全书初始条件。**

---

## 🛠️ 解法：先建立故事发动机，再生成全书设定

这个 Skill 把新书创建理解成一条因果链：

```text
作者真正想写什么
        │
        ▼
这本书承诺给读者什么
        │
        ▼
世界用什么规则持续制造压力
        │
        ▼
角色为什么必须做出有代价的选择
        │
        ▼
哪些利益 / 价值不能同时满足
        │
        ▼
开书事件制造什么不可逆后果
        │
        ▼
证明这套结构足以支撑长篇继续运转
```

对应五个交互阶段：

```text
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 创作原点  │ → │ 世界设定  │ → │ 角色设定  │ → │ 冲突种子  │ → │ 终审确认  │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
     │               │               │               │               │
     ▼               ▼               ▼               ▼               ▼
 意图/爽点/红线     压力/利益/代价     欲望/能力/认知     不可轻易化解       健康检查后
 题材真正用途       七类世界核心      关系与知识边界      +开书初始事件       生成最终设定
```

**核心差异**：后一个阶段不是重新发明前面的内容，而是用新的设定去**兑现、验证和补强前面的承诺**。

---

## 💬 不是问卷，而是“代入已有设定”的苏格拉底追问

传统设定助手经常问：

> 你的核心主题是什么？  
> 你的世界规则是什么？  
> 你的人物弧光是什么？

这些问题没有错，但作者往往拥有的是**画面、感觉、爽点、一个人物、一个“不想写成那样”的直觉**，而不是现成的编剧术语。

纵横开书架构师会把抽象问题改造成：

> **已有设定 + 真正要决定的问题 + 3～5 个来自这本书自身的具体选项。**

例如已经确定“末世 + 重生”：

> 本书当前是“末世重生”。你最不想把这本书写成哪种常见套路？
>
> A. 靠反复死亡不断重来，把失败成本变成零  
> B. 频繁时间重置，让已经发生的后果被清空  
> C. 重生同时无代价恢复修为、装备或资源  
> D. 主角明知未来却仍反复踩前世已经知道的低级坑  
>
> **只选最不能接受的一项。**

这不是让 AI 替作者做决定。

它的作用是：**把作者脑中的模糊偏好变成一个会影响后续架构的明确选择。**

如果作者回答仍然模糊，AI 优先保持原来的核心问题，只根据最新回答换一组更贴近本书的选项，而不是不断换问题把创作带偏。

## 💎 这个 Skill 真正多做了什么？

### 1. 先找“创作原点”，再自动生成设定

一般设定生成器从“世界是什么、主角是谁”开始。

纵横开书架构师先确认：

- 作者为什么想写这本书；
- 最想提供什么情绪和爽点；
- 核心创新是什么；
- 哪些常见套路最不能接受；
- 什么东西应该成为几十万字都要持续兑现的承诺。

因为后续世界、角色和冲突都应该**服务这个核心意图**，而不是各自生成一套看起来很丰富的资料。

---

### 2. 题材不是标签，而是“读者承诺的功能模块”

Skill 内置题材组合知识，但不会简单告诉你：

```text
科幻 + 末世 + 重生 + 系统
```

而会继续问：

- “末世”主要负责资源匮乏、秩序崩坏，还是未知威胁？
- “重生”负责先知优势、弥补遗憾，还是重新理解前世错误认知？
- “系统”负责成长反馈、信息能力，还是组织经营？
- 这些优势为什么不能让主角一路平推？
- 最容易写崩的套路是什么？

最终把标签压成一条故事因果：

```text
重生提供先知优势
        +
末世持续破坏资源与秩序
        +
系统提供可控成长
        +
科幻规则要求技术与能源代价
        +
主角越改变历史，先知优势越失真
```

这样题材、爽点和世界规则会直接进入后续设定，而不是停留在简介标签里。

---

### 3. 世界设定不是百科，而是一套“压力系统”

纵横的新书设定需要的不只是：

> 有几个国家、几种能源、多少职业等级。

更重要的是每个强设定能回答：

```text
它限制了谁
   ↓
给谁利益
   ↓
需要付什么代价
   ↓
因此逼出了什么人物选择或冲突
```

因此 Skill 会覆盖：

- 规则；
- 地理；
- 资源；
- 势力；
- 职业 / 超能力 / 成长体系；
- 怪物 / 灾难 / 非人格化威胁；
- 关键历史大事。

但不会为了“显得世界很大”去生成与主线无关的百科资料。

---

### 4. 角色不是人物卡，而是“选择发动机”

普通人物卡常见字段是：

> 姓名、年龄、外貌、性格、背景。

纵横开书阶段还需要知道：

- 他最想得到什么；
- 最怕失去什么；
- 为什么现在必须行动；
- 价值排序和底线是什么；
- 能力 / 资源有什么代价和限制；
- 哪段关系最能改变他的选择；
- 他**知道什么、不知道什么、错误相信什么、合理怀疑什么**；
- 他最可能走向成长、堕落、错位还是稳定。

其中“知识边界”尤其重要。

因为后续不管由纵横还是其他 AI 继续写，角色都不应该因为“AI 知道世界真相”就自动获得上帝视角。

---

### 5. 关系只保留“会改变选择”的关系

不是把所有人物两两连线。

真正进入核心设定的关系需要说明：

- 为什么彼此需要；
- 什么利益是一致的；
- 什么矛盾无法轻易消失；
- 双方各自害怕对方什么；
- 谁知道对方不知道的东西；
- 这段关系如何进入主线冲突。

这样人物关系才能在后续剧情里自己产生作用力。

---

### 6. 冲突不是一句“主角对抗反派”

Skill 会建立多个冲突种子，并确认：

- 谁和谁；
- 什么利益或价值不能同时满足；
- 双方争夺什么；
- 失败会失去什么；
- 为什么不能靠一次沟通解决；
- 它依赖哪些人物和世界规则。

最终再融合出一个**开书核心初始剧情段**。

它不是全书大纲，而是用一个真实事件验证：

> **这个世界真的会施压吗？这个人物真的会这样选择吗？这个冲突真的会产生不可逆后果吗？**

如果答案是否定的，说明前面的设定还没有形成故事发动机。

---

### 7. “负面清单”让设定同时说明绝不能怎么写

普通 Story Bible 通常只记录“是什么”。

纵横开书设定还会记录：

> **这本书最不能被写成什么。**

来源包括：

1. 作者明确防雷；
2. 当前题材最常见的写崩方式；
3. 由本书自身逻辑推导出的禁区。

例如：

```text
不能让重生者无理由重复犯已经知道的低级错误
不能让系统替主角完成核心价值选择
不能让稀缺资源无来源地无限生成
不能让角色知道其知识边界之外的信息
不能为了化解剧情临时修改世界规则
```

它既能帮助纵横后续生产保持方向，也非常适合作为其他 AI 写作工具的长期负向约束。

---

### 8. 每阶段固化事实，降低长对话“越聊越忘”

每完成一个阶段，Skill 会生成一张**阶段事实卡**：

```text
已确认事实
本阶段核心因果
跨阶段绑定
负面约束
暂留后续解决的问题
```

用户确认后，它成为后续设定生成的事实锚点。

在支持文件读写的 Agent / Codex 环境里，还可以维护：

```text
NEW_BOOK_CANON.md
```

最终设定必须从这些已经确认的事实重组，而不是让 AI 在最后一轮凭印象重新总结一遍。

---

### 9. 最终不是“生成完了”，而是先做一次全书健康检查

用户确认定稿后，Skill 会先检查：

| 健康度 | 检查什么 |
|---|---|
| 📋 **设定完整性** | 核心字段是否齐全，并且每项都有实际叙事作用 |
| 💎 **商业性与卖点** | 一句话概念、差异化、爽点兑现、同质化与长篇升级空间 |
| 🎭 **角色健康度** | 主动选择、欲望恐惧、优势代价、知识边界、人物弧光 |
| 🌍 **世界健康度** | 七类世界设定是否互相支撑，强设定是否有成本和边界 |
| 🔗 **设定—角色—剧情一致性** | 人会不会这样做、世界允不允许、信息是否越界、后果是否成立 |
| 🚫 **负面清单** | 防雷、题材风险、本书自身的逻辑禁区 |

结果只分：

```text
通过 / 建议优化 / 阻塞
```

有阻塞先修复，再生成最终设定。

## 📦 最终生成的是什么？

输出是一份**人类可读、完整、自洽的新书核心设定文档**，不是数据库 JSON，也不是软件私有格式。

```text
《书名》新书核心设定
├─ 作品基础信息
├─ 创作原点
├─ 世界设定
│  ├─ 规则
│  ├─ 地理
│  ├─ 资源
│  ├─ 势力
│  ├─ 职业 / 超能力 / 成长体系
│  ├─ 怪物 / 灾难 / 非人格化威胁
│  └─ 关键历史大事
├─ 核心角色组
├─ 重要人物关系
├─ 冲突种子池
├─ 开书核心初始剧情段
├─ 全局因果链
├─ 本书负面清单
└─ 可选优化建议
```

这份文档设计成**可迁移的创作资产**。

### 交给纵横

它覆盖纵横新书创建阶段所需的核心业务设定，可以直接作为新书初始化资料使用。

### 交给其他 AI 写作工具

它本身就是一份高密度 Story Bible，可以作为：

- 项目知识库；
- System / Project Instructions 的设定来源；
- 大纲生成前置资料；
- 角色扮演 / 多 Agent 推演资料；
- 长篇正文生成的固定参考。

### 作者自己使用

即使完全不使用任何软件，它也可以作为作者的：

- 全书设定总纲；
- 人物与世界检查表；
- 创作红线；
- 开书前架构审稿材料。

## 🔗 它在「纵横叙事引擎」中的位置

纵横叙事引擎的目标是：

> **百万字小说不跑偏的 AI 叙事引擎。**

纵横开书架构师负责其中最前面的一个问题：

> **在小说真正开始长期运行之前，先把“什么是这本书”建立清楚。**

```text
作者的一句话 / 灵感 / 人物 / 爽点
                │
                ▼
┌───────────────────────────┐
│       纵横开书架构师       │
│                           │
│ 苏格拉底追问创意与意图     │
│        ↓                  │
│ 题材 / 爽点 / 世界 / 人物  │
│        ↓                  │
│ 关系 / 知识边界 / 冲突     │
│        ↓                  │
│ 开书初始事件 + 健康检查     │
└───────────────────────────┘
                │
                ▼
       《新书核心设定》
                │
        ┌───────┴────────┐
        ▼                ▼
   纵横新书创建       其他 AI / 作者
        │
        ▼
   后续长期叙事生产
```

它不替代纵横后续的剧情运行、角色推演、审计和正文生产。

它负责的是更上游的一件事：

> **让后续系统得到的不是一堆“看起来像设定”的文字，而是一组作者已经确认、互相有因果关系、能够真正驱动故事的初始事实。**

详细说明见 [docs/在纵横新书创建中的作用.md](docs/在纵横新书创建中的作用.md)。

## 🚀 快速开始

把当前 Skill 文件放到支持 Skill / Agent 指令的环境中，例如：

```text
SKILL.md
```

然后只需要说：

```text
我想开一本新书。
```

或者直接给它一个很不完整的灵感：

```text
我想写一本末世重生。
主角前世建过一个很大的幸存者基地，
但最后发现真正毁掉文明的不是怪物。
我不想写成单纯囤货爽文。
```

它应该从你**已经说出的内容**继续往下追问，而不是让你重新填写一套表格。

完整交互形态见 [docs/交互示例.md](docs/交互示例.md)。

## 🎯 适合谁？

- 想让 AI 帮自己把模糊创意“想深、想完整”的小说作者；
- 想快速获得完整 Story Bible，再交给其他 AI 工具继续生产的人；
- 不喜欢填写复杂设定表，但愿意对关键创作选择做判断的人；
- 希望为百万字长篇提前建立角色、世界和冲突约束的人；
- 使用纵横叙事引擎，希望直接完成新书初始化的人。

---

## ⚠️ 它不做什么？

它专注**全书核心设定初始化**，因此不会：

- 生成未来几十章的章节计划；
- 提前写完整分卷大纲；
- 直接生成正文；
- 用商业评分替作者决定创作方向；
- 用一堆数据库字段破坏创作交互；
- 假装任何设定都已经“绝对完整”。

它只把真正需要在开书前决定的事情做深、做稳。

## 🙌 一句话总结

> **纵横开书架构师不是替作者“批量生成设定”，而是用交互把作者真正想写的东西变成世界、人物和冲突都必须遵守的初始事实。**
>
> **一次把书想对，后面的 AI 才有机会一直写对。**
